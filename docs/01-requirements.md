# 01. 前提・制約・要件

最終更新: 2026-09-06（計画ラウンド4完了時点）

## 1. ハードウェア

- Mac Studio: M3 Ultra、32コアCPU、80コアGPU、32コアNeural Engine
- Unified Memory: 512GB
- 内蔵SSD: 8TB
- 台数: 1台

## 2. 利用者プロファイル（設計に必要な範囲のみ）

- 暗号資産（Bitcoin中心、Ethereum系も利用）を自己管理する長期保有者
- 日常OSは Tails。プライバシー・匿名性への要求水準が高い
- ウォレット: Electrum（Bitcoin）、MetaMask（Ethereum系）
- シードフレーズは紙で保管。ハードウェアウォレット・マルチシグは未導入
- 技術的立ち位置: エンジニア職ではない。運用は本人が一人で行う
- ターミナル習熟度: 手順書からのコピペ実行はできる。エラー時の自力調査は前提にしない
- 目的: 生活・仕事の生産性向上（収益化や研究成果が主目的ではない）
- 追加予算: **なし**。ハードウェアウォレット等の購入は行わず、無料で完結する構成のみ採用する

### 手元の機器

- Mac Studio（本機）
- Tails を起動している x86 PC（署名・ウォレット操作用として継続利用）
- スマートフォン（外出先からの確認・通知用途の候補）
- モニター・キーボード・マウス（本機の直接操作が可能）

## 3. 確定した方向性

**「自分専用の検証インフラ」＋「秘匿性の高い作業環境」** を1台に同居させる。

採用する構成要素:

1. Bitcoin フルノード ＋ 自前 Electrum サーバー（Fulcrum または electrs）
2. ローカル LLM（外部に問い合わせ内容を送らないリサーチ・作業支援）
3. ポートフォリオ監視・オンチェーン分析ダッシュボード（自ノードのデータのみを使用）

計画から外した構成要素:

- Ethereum フルノード（ADR-005 参照。P2P が Tor を通せないため、全通信 Tor の方針と両立しない）

## 4. 制約

### 4.1 OS の制約

- Tails は Intel/AMD 向け USB 起動 OS であり、Apple Silicon では起動できない
- したがって本機は macOS で運用する。Tails は別筐体（x86 PC）で継続利用する前提
- Asahi Linux は M3 世代を実用水準でサポートしていないため、Linux ネイティブ運用は採らない

### 4.2 鍵の取り扱い（最重要）

- 本機は常時ネット接続の高性能マシンであり、**秘密鍵・シードを一切置かない**
- 本機の役割は「検証・監視・計算」に限定する（watch-only）
- 署名は本機の外（Tails 環境）で行う。ハードウェアウォレットは購入しない（予算ゼロ方針）
- 予算ゼロで安全性を上げる案として、Tails を「オンライン用」と「署名専用（ネット未接続）」に
  分け、PSBT を QR / USB で受け渡す運用を検討する（ADR-006）

### 4.3 ネットワーク

- 自宅の光回線、24時間稼働可
- **全通信を Tor 経由**にする（Tails と同等の匿名性水準）
  - Bitcoin Core は onion-only 運用が可能
  - Ethereum は Tor と両立しないため計画から除外した（ADR-005）
  - LLM モデル等の大容量ダウンロードを Tor 経由にするかは要判断

### 4.4 公開リポジトリ

- 本リポジトリは public。個人属性・資産額・実 IP・鍵関連情報は記載禁止

## 6. 脅威モデル（利用者が警戒する順に対策を割り当てる）

| 脅威 | 本計画での主な対策 |
|---|---|
| マルウェア・遠隔侵入 | 本機に鍵を置かない（ADR-002）。本機で日常のブラウジングをしない（ADR-008）。受信ポートを開けず onion サービスのみで公開。macOS の標準防御（Gatekeeper、SIP、FileVault）を有効に保つ。ソフトは公式配布元のみ、署名検証を手順化 |
| 通信監視・身元の紐付け | 全通信 Tor（ADR-003）。Bitcoin Core は onion-only。ローカル LLM により検索・質問内容を外部に出さない。自宅 IP から「Bitcoin ノード」「LLM 利用者」と見えないようにする |
| 物理的な盗難・侵入・強要 | FileVault によるフルディスク暗号化と強いログインパスワード。本機には鍵がないため、奪われても資産は失われない。紙のシードの保管場所は本機と分ける。強要への対策は本計画の範囲外（別途検討） |
| 自己ミス・紛失 | 手順書をコピペ完結にする（ADR-007）。設定ファイルをこのリポジトリで版管理する（秘密情報は除く）。送金前チェックリストと、少額テスト送金の手順を用意する |
