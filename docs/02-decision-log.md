# 02. 設計判断ログ（ADR）

書式: 番号 / 日付 / 状態 / 判断 / 理由 / 影響

## ADR-001: 本機の用途を「自己主権型検証インフラ＋秘匿作業環境」とする

- 日付: 2026-09-06
- 状態: 採用
- 判断: 汎用ホームラボではなく、暗号資産の自己検証（フルノード群）と、
  外部に情報を出さない作業環境（ローカル LLM・ダッシュボード）に用途を集中させる
- 理由: 利用者が自己管理の長期保有者であり、他者のサーバーへの依存（公開 Electrum サーバー、
  Infura 等）が最大のプライバシー・信頼リスクである。512GB メモリと 8TB SSD は
  Bitcoin・Ethereum フルノード＋大規模 LLM の同居に十分な余裕がある
- 影響: 映像制作・ゲーム等の用途は計画対象外とする

## ADR-002: 本機には秘密鍵を置かない（watch-only 原則）

- 日付: 2026-09-06
- 状態: 採用
- 判断: 本機は xpub / アドレスの監視と検証のみを行う。署名は別環境で行う
- 理由: 常時オンライン・多機能なマシンは攻撃面が広い。役割を分離することで、
  本機が侵害されても資産が直接失われない構造にする
- 影響: Electrum は本機を「サーバー」としてのみ使い、ウォレット本体は Tails 側に残る

## ADR-003: 全通信を Tor 経由とする（例外は個別に ADR で記録）

- 日付: 2026-09-06
- 状態: 採用（例外検討中）
- 判断: 本機からの外部通信は原則 Tor を通す
- 理由: 利用者の匿名性要求が Tails 同等であるため
- 影響: Bitcoin Core は onion-only で構成可能。Ethereum P2P と大容量ダウンロードは
  例外扱いとするか次ラウンドで決定する

## ADR-004: 本機は macOS で運用する

- 日付: 2026-09-06
- 状態: 採用
- 判断: ホスト OS は macOS。Linux が必要なサービスは VM またはコンテナで動かす
- 理由: Tails・Asahi Linux ともに M3 Ultra では動作しないため
- 影響: 各サービスの配置（ネイティブ / VM / コンテナ）は別途決める

## ADR-005: Ethereum ノードを計画から除外する

- 日付: 2026-09-06
- 状態: 採用
- 判断: Ethereum 実行クライアント／コンセンサスクライアントは構築しない
- 理由: Ethereum の P2P は UDP を用いる discovery を必須とし、Tor を通せない。
  clearnet や VPN の例外を設ける案もあったが、利用者は「全通信 Tor」を優先して除外を選択した
- 影響: MetaMask の運用は現状のまま（本計画の対象外）。本機の SSD・帯域は Bitcoin と LLM に集中できる

## ADR-006: 鍵保管は購入なしで改善する（watch-only ＋ Tails 署名分離）

- 日付: 2026-09-06
- 状態: 採用（分離運用の詳細は設計フェーズで具体化）
- 判断: ハードウェアウォレットは購入しない。本機は xpub による watch-only、署名は Tails で行う。
  追加費用なしの改善として、Tails を「オンライン用」と「署名専用（ネット未接続）」の
  2 本に分け、PSBT（未署名取引）を QR コードまたは USB で受け渡す運用を提案する
- 理由: 利用者の予算ゼロ方針。Electrum は PSBT のエクスポート／インポートと
  オフライン署名を標準でサポートしており、追加ソフトなしで実現できる
- 影響: 送金時の手順は増えるが、オンライン環境に秘密鍵が存在する時間をゼロにできる。
  紙のシードの保管方法（耐火・耐水・分散）はハードウェア購入を伴うため、提案に留める

## ADR-007: 手順書は「コピペで完結」を基準にし、GUI ツールを優先する

- 日付: 2026-09-06
- 状態: 採用
- 判断: すべての構築・運用手順は、1 行ずつ意味を添えたコピペ可能なコマンドとして書く。
  GUI で済むもの（Bitcoin Core の bitcoin-qt、LLM のチャット UI 等）は GUI を採用する
- 理由: 利用者のターミナル習熟度がコピペ実行レベルであるため。
  エラー時に自力で調査する前提を置かない
- 影響: 自動化スクリプトは「実行するだけ」の形にまとめ、設定ファイルは完成形を提示する。
  複雑な Docker 構成より、macOS ネイティブで動く単純な構成を優先して検討する

## ADR-008: 本機はサーバーと LLM 専用とし、日常利用はしない

- 日付: 2026-09-06
- 状態: 採用
- 判断: 本機で Web ブラウジング、動画視聴、一般アプリの利用は行わない。
  ウォレット操作と日常作業はこれまで通り Tails で行う
- 理由: 攻撃面の最小化。macOS 上の日常利用は Tails と同等の匿名性を持たず、
  ブラウザ経由のマルウェア感染が本機の全サービスを危険に晒す
- 影響: 本機上のブラウザは、ローカルの管理画面（LLM の UI、ダッシュボード）を開く用途に限定する。
  Homebrew 等のパッケージ取得も Tor 経由に統一する

## ADR-009: 外部からのアクセスはすべて Tor onion サービス経由にする

- 日付: 2026-09-06
- 状態: 採用
- 判断: 本機上の各サービス（Electrum サーバー、LLM の Web UI、ダッシュボード）は
  それぞれ onion アドレスで公開し、Tails PC と Android からは Tor 経由で接続する。
  ルーターのポート開放や LAN 内平文接続は行わない
- 理由: 自宅 LAN 内でも通信経路を統一でき、外出先からも同じ手順で使える。
  onion サービスは受信ポートを開けないため、インターネット側からの攻撃面がゼロになる。
  クライアント認証付き onion（v3 client auth）を使えば、アドレスを知られても第三者は接続できない
- 影響: 各サービスに Tor の hidden service 設定が必要。Android は Orbot または Tor Browser、
  Electrum Android も onion 接続に対応している
