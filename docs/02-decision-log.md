# 02. 設計判断ログ（ADR）

書式: 番号 / 日付 / 状態 / 判断 / 理由 / 影響

## ADR-001: 本機の用途を「自己主権型検証インフラ＋秘匿作業環境」とする

- 日付: 2026-09-06
- 状態: 採用
- 判断: 汎用ホームラボではなく、暗号資産の自己検証（フルノード群）と、
  外部に情報を出さない作業環境（ローカル LLM・ダッシュボード）に用途を集中させる
- 理由: 利用者が自己管理の長期保有者であり、他者のサーバーへの依存（公開 Electrum サーバー、
  Infura 等）が最大のプライバシー・信頼リスクである。512GB メモリと 8TB SSD は
  Bitcoin・Ethereum フルノード＋大規模 LLM の同居に十分な余裕がある
- 影響: 映像制作・ゲーム等の用途は計画対象外とする

## ADR-002: 本機には秘密鍵を置かない（watch-only 原則）

- 日付: 2026-09-06
- 状態: 採用
- 判断: 本機は xpub / アドレスの監視と検証のみを行う。署名は別環境で行う
- 理由: 常時オンライン・多機能なマシンは攻撃面が広い。役割を分離することで、
  本機が侵害されても資産が直接失われない構造にする
- 影響: Electrum は本機を「サーバー」としてのみ使い、ウォレット本体は Tails 側に残る

## ADR-003: 全通信を Tor 経由とする（例外は個別に ADR で記録）

- 日付: 2026-09-06
- 状態: 採用（例外検討中）
- 判断: 本機からの外部通信は原則 Tor を通す
- 理由: 利用者の匿名性要求が Tails 同等であるため
- 影響: Bitcoin Core は onion-only で構成可能。Ethereum P2P と大容量ダウンロードは
  例外扱いとするか次ラウンドで決定する

## ADR-004: 本機は macOS で運用する

- 日付: 2026-09-06
- 状態: 採用
- 判断: ホスト OS は macOS。Linux が必要なサービスは VM またはコンテナで動かす
- 理由: Tails・Asahi Linux ともに M3 Ultra では動作しないため
- 影響: 各サービスの配置（ネイティブ / VM / コンテナ）は別途決める
